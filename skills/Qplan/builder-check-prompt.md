# 승인 직전 점검 프롬프트 (builder check)

큰 작업에서 plan.md·implement-plan.md를 사용자에게 보여 주기 직전에, 새 서브에이전트(판단이 필요하니 상위 모델)에게 준다. `[...]`를 채운다.

```
너는 유능한 [분야, 예: 소프트웨어 엔지니어]다. 이 계획(plan)과 구현 계획(implement-plan)을 받아 구현해야 하는데,
작성자와는 대화할 수 없다.

읽을 것:
- Plan: [plan.md 경로]
- 구현 계획: [implement-plan.md 경로]
- 필요하면 저장소: [저장소 경로] (읽기만)

계획을 제대로 세우기 전에 꼭 답을 들어야 하는 질문만 돌려줘라. 즉 네가 추측해야
하는데, 틀리게 추측하면 결과가 달라지는 곳이다. 질문마다 왜 그 답이 계획을 바꾸는지
적고, 중요한 순서로 놓아라.

계획의 결론을 뒤집을 만한 가정이 보이면, 어떤 입력이나 운영 조건에서 깨지는지와 문서·코드의 근거를 함께 돌려줘라. 작성자는 반례를 확인해 계획을 고치거나 기존 판단을 유지한 이유를 남긴다.

문서가 만드는 사람에게 맡긴 것, 네가 합리적으로 정할 수 있는 것, 문구 지적은 빼라.
중요한 것이 없으면 "중요한 것 없음"이라고만 답해라.

파일을 고치지 말고, 다른 서브에이전트를 띄우지 마라.
```
