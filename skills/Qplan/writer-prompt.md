# 계획 작성자 프롬프트

서브에이전트 인계에서 조율하는 창(인터뷰 창)이 plan.md·implement-plan.md 작성을 작업자에게 맡길 때 쓴다. `[...]`를 채운다.
작업자는 Q 스킬을 부르지 않고 사용자에게 묻지도 못한다. 그래서 `Qplan`이 쓰는 쪽에 정한 것을 이 프롬프트와
절대 경로로 넘기고, 승인 직전 점검·사용자 질문·승인은 조율자가 `Qplan`대로 한다. 첫 작성과 승인 전 수정
(builder check 답, 사용자 질문의 답, 사용자 수정 요청 반영) 모두 이 프롬프트로 맡긴다. 수정이면 "수정 모드" 줄을 채운다. 경로는 이 스킬이 로드된
디렉터리를 기준으로 절대 경로로 채운다(상대 경로는 서브에이전트가 찾지 못한다).

```

## 읽을 것
- 확정된 의도: [intent.md 절대 경로] — 이유·완료 기준·하지 않을 일. 이것이 기준이다.
- 쓰는 규칙: [Qplan SKILL.md 절대 경로]의 "문서 위치", "plan.md 쓰기", "implement-plan.md 쓰기",
  "스스로 검토" 절만 따른다. 승인 직전 점검과 승인 절은 내가 한다.
- 양식: [plan-template.md 절대 경로], [implement-plan-template.md 절대 경로]
- 저장소: [저장소 경로] (읽기만)

## 쓸 곳
[작업 폴더 절대 경로]의 plan.md, implement-plan.md. 두 문서의 상태는 "초안"으로 둔다(승인됨은 조율자가 적는다). 코드는 쓰지 않는다.

## 수정 모드 (승인 전 고칠 때만)
[반영할 것: builder check 답, 사용자 답, 수정 요청을 그대로]. 이미 쓴 두 문서를 읽고 이것만 반영한다. 답이 다른 단계나
"내가 정한 것"을 바꾸면 그것도 맞춰 고치고 보고에 적는다.

## 버그일 때 (해당하면)
계획 전에 원인을 조사한다: 재현하고, 실패 지점을 코드에서 찾고(경로:줄), 가설을 하나씩 확인한다. 원인과 근거를
plan.md에 남기고, 원인을 확인하기 전에는 고칠 방법을 정하지 않는다. 증상만 덮는 계획은 같은 버그를 다시 부른다.

## 할 일
1. intent.md와 저장소를 읽고 지금 동작과 바뀔 곳을 확인한다.
2. 쓰는 규칙대로 두 문서를 쓴다. 사용자가 정한 것과 네가 정한 것을 나누고, 네가 정한 것에는 이유를 단다.
3. 접근은 사용자가 고른 것([고른 접근])을 따른다. 쓰다가 결과가 달라질 다른 길이 보이면 바꾸지 말고 보고에 적는다.
4. 실행 방식(서브에이전트 / 직접)은 정하지 않는다. 사용자가 승인 때 고른다. 추천이 있으면 근거와 함께 보고한다.

다른 서브에이전트를 띄우지 마라. Q로 시작하는 스킬도 부르지 마라. 조율(점검·질문·승인)은 내가 하고,
네가 따를 규칙은 위 "읽을 것"에 있다. 사용자에게 물을 것은 묻지 말고 보고에 모아라.

- 실행 방식 추천과 근거
```
