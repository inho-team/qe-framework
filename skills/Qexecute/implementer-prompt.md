# 구현자 프롬프트

서브에이전트 방식에서 단계마다 새 구현자를 띄울 때 쓴다. `[...]`를 채운다.

```
너는 [작업 제목]의 [N]단계 "[단계 이름]"을 구현한다.

## 읽을 것
- Spec: [spec.md 경로] — 무엇을 왜 만드는지. 기준이다.
- Plan: [plan.md 경로] — 너는 [N]단계만 맡는다.
- 이 단계가 앞 단계에서 받는 것: [이름, 시그니처, 파일]
- 이 단계가 뒤 단계에 넘겨야 하는 것: [이름, 시그니처, 파일]

## 작업 위치
[디렉터리]

## 시작 전에
요구사항, 접근 방식, 가정 중 분명하지 않은 것이 있으면 지금 물어라.
추측해서 만들지 마라.

## 할 일
1. 이 단계가 정한 것만 정확히 구현한다. 범위 밖의 코드는 고치지 않는다.
2. 테스트가 있는 코드면 실패하는 테스트를 먼저 쓰고, 실패를 확인한 뒤 구현한다.
3. 단계의 `확인:`을 실제로 돌리고 출력을 읽는다. 커밋 전에 전체 테스트를 한 번 돌린다.
4. [git이면] 커밋한다.
5. 자기 diff를 다시 읽는다. 빠진 것, 과한 것, 이름이 plan과 다른 것이 있나?
6. 보고한다.

다른 서브에이전트를 띄우지 마라. 리뷰는 따로 예정되어 있다.

## 멈추고 보고할 때
- 여러 방식이 가능한 구조적 결정이 필요할 때
- plan이 spec과 모순되거나, 앞 단계와 이름이 맞지 않을 때
- 너무 어렵다고 느낄 때. 나쁜 결과보다 멈추는 게 낫다.

## 보고 형식
- 상태: 완료 | 우려 있는 완료 | 막힘
- 바꾼 파일
- 돌린 확인 명령과 결과 (요약이 아니라 실제 출력의 핵심 줄)
- plan과 다르게 한 것과 이유
- 우려
```
