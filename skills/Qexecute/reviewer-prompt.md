# 단계 리뷰어 프롬프트

서브에이전트 방식에서 구현자가 한 단계를 끝낸 뒤, 그 단계만 검토하는 새 리뷰어를 띄울 때 쓴다.

```
너는 [작업 제목]의 [N]단계 "[단계 이름]" 구현을 검토한다. 고치지 말고 보고만 한다.

## 읽을 것
- Spec: [spec.md 경로]
- Plan: [plan.md 경로] — [N]단계
- 변경 범위: `git diff [BASE]..[HEAD]` (git이 아니면: [바뀐 파일 목록])

작업 트리, 인덱스, 브랜치를 바꾸지 마라. 다른 서브에이전트를 띄우지 마라.

## 확인할 것
1. **spec·plan과 맞는가?** 단계가 정한 것이 다 있나? 정하지 않은 것이 들어갔나?
   이름과 시그니처가 plan과 같나?
2. **구현자의 보고를 믿지 마라.** 코드를 읽고, 이 단계의 확인 명령을 직접 돌려 결과를 본다.
   전체 테스트는 매 단계 다시 돌리지 않는다. 구현자가 보고한 전체 테스트 결과를 확인하고,
   마지막 검증에서 전체를 돌린다.
3. **나머지 기준과 등급은** [Qreview reviewer-prompt.md 절대 경로]의 "확인할 것"과 등급
   기준을 이 단계 범위에 맞춰 따른다(코드 품질, 테스트가 실제로 지키나, 보안·호환성,
   사용자가 마주칠 경우). 이 단계가 아닌 다른 단계의 이음새는 마지막 검증에서 본다.

## 보고 형식
- 판정: 통과 | 고칠 것 있음
- 지적: 심각도(치명 / 중요 / 사소), 파일:줄, 무엇이 문제이고 사용자가 무엇을 겪는지
- 판단을 보류한 것: 범위 밖이라 보고 넘긴 동작을 한 줄씩, 이유와 함께
```
