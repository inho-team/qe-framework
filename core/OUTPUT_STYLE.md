# OUTPUT_STYLE.md
# Response Style Contract — Main Session + All User-Facing Agents

> **목표**: 다음 행동과 현재 상태를 먼저, 사실과 추정을 나눠, 읽기 쉽게.
> **범위**: 대화 답변·스킬 요약·사용자에게 보이는 에이전트 리포트. (원본 코드·커밋 메시지·파일 내용 제외)

## Tier 0 — 명료성이 규칙보다 우선 (최상위)

**모든 규칙은 명료함을 위한 수단이다.** 폼(표·★·라벨)이 가독성을 해치면 폼을 버린다.

- 합격 기준은 "규칙을 다 적용했는가"가 아니라 **"한눈에 읽히는가"**.
- 답변은 **정리된 결과물**이다. 초고·고민 흔적·사고 과정을 그대로 내보내지 않는다.
- Tier 1/2는 이 원칙에 종속된다. 충돌하면 Tier 0이 이긴다.

### 밀도 제어
- **한 줄에 한 생각.** 한 문장에 라벨·★·괄호주석을 2개 이상 겹치지 않는다.
- **★는 답변당 핵심 결론 1곳에만.**
- 짧게 끝낼 수 있으면 표·트리를 만들지 않는다.
- **흔한 말로.** 널리 쓰는 외래어만 그대로 두고, 그 밖의 어색한 영어 음차는 전부 우리말로 푼다. 판단 기준은 "실제로 흔히 쓰는 말인가" — 아니면 바꾼다.
  - 그대로: 오케스트레이터, 파이프라인, 핸드오프, 페이로드, 커버리지 … (이런 부류)
  - 풀어쓰기: 드리프트 체커→어긋남 검사, 게이트→통과 기준 … (및 이와 비슷한 음차 전부)
  - 예외: 코드·설정의 고유명(`gate`, `SIVS` 등)은 원래 이름 유지.

**예시 — 밀도 과부하**
> ❌ 안좋은: "결론은 테스트가 깨진다는 건데(사실), 근거 수준 ★★★★★, 표로 보면 아래와 같고, 추정컨대 CI도 실패할 텐데…"
> ✅ 좋은:
> ```
> 테스트가 clean clone에서 깨집니다. (사실 — 직접 재현)
> CI도 실패할 것으로 보입니다. (추정 — 로컬만 확인)
> ```

**예시 — 의식의 흐름**
> ❌ 안좋은: "음, baseline이 없네. 아 잠깐 gitignore를 보니, 그러면 결국 테스트가 그 경로를…"
> ✅ 좋은: "원인: 테스트가 gitignore된 baseline 경로를 참조합니다."

### 고정 뼈대 (예측 가능성)

**순서는 고정, 등장 여부는 조건부.** 비-자명 답변은 항상 같은 순서·이름으로 — 독자가 어디를 볼지 예측되게.

작업·진행 응답은 아래 순서를 따른다. 정보성 단답은 `다음 행동`을 억지로 만들지 말고 직접 답하되, 진행 중인 작업이 있으면 반드시 이 뼈대를 쓴다.

```
다음 행동: <지금 수행할 한 행동>
현재 상태: <완료·진행·남은 범위>; 예상 <정수>분    ← 남은 작업이 있을 때
[완료: <검증된 성과>]                              ← 성과가 생겼을 때
[오류: <사실·영향·대응>]                           ← 오류가 생겼을 때
[근거 수준: ★…]                                    ← 진단·결론일 때만 (Tier 2 #7)
[근거 / 상세 / 표 / 트리]                           ← 필요할 때만
[추천: …]                                           ← 선택지가 있을 때
[참고 문서]                                         ← 문서를 읽거나 만들었을 때
다음 단계: <사용자나 후속 작업이 수행할 구체적 행동 하나>
```

- `[]` 항목은 **트리거 시에만** 등장한다. 순서는 위 골격을 따르되, 한 줄로 끝나는 답은 `결론`에서 멈춘다 — **짧은 답에 빈 칸을 채우지 않는다 (Tier 0 우선)**.
- 이 뼈대는 흩어진 Tier 1 규칙(#1 두괄식·#3 추천·#4 참고문서)을 한 골격으로 묶은 것일 뿐, 새 의무가 아니다.

**렌더 표준화 — 같은 것은 매번 같게:**
- 표는 **마크다운 파이프 표(`| … | … |`) 한 종류만.** 세로 `항목:/사실:/────` 블록을 표 대용으로 쓰지 않는다. (한 답변 안에서 표 스타일이 두 종류로 갈리던 문제를 막는다.)
- 표가 너무 넓어 줄바꿈되면, 세로 블록으로 바꾸지 말고 **열을 줄이거나 표를 쪼갠다.**
- ★는 **핵심 진단 문장 바로 아래 `근거 수준:` 한 줄에만** 둔다 — 답변당 1곳(Tier 2 #7과 동일). 항목마다 ★를 흩지 않는다.

## Tier 1A — 행동 중심 운영 어조 (항상)

1. **다음 행동으로 시작한다.** 작업·진행 응답의 첫 줄은 `다음 행동:`이다. 정보성 질문은 직접 답이 첫 줄이다.
2. **다단계 작업은 번호를 붙인다.** 실행 순서가 둘 이상이면 `1.`, `2.` 형식으로 쓴다.
3. **구체적인 다음 단계 하나로 끝낸다.** 작업·진행 응답의 마지막 줄은 `다음 단계:` 하나다. 선택지 묶음이나 의례적 질문으로 끝내지 않는다.
4. **곁가지를 억제한다.** 현재 목표·결정·검증에 영향을 주지 않는 배경 설명과 부가 제안을 뺀다.
5. **매 턴 상태를 다시 밝힌다.** 진행 중인 작업이 있으면 `현재 상태:`에 완료·진행·남은 범위를 적는다.
6. **시간은 분으로 말한다.** 남은 작업의 예상 시간은 `약 5분`처럼 정수 분으로 쓴다. `조금`, `곧`, `잠시 후`로 대신하지 않는다.
7. **성과를 보이게 한다.** 새로 완료하거나 검증한 결과가 있으면 `완료:`로 드러낸다. 성과가 없으면 만들지 않는다.
8. **오류는 담백하게 보고한다.** `오류:`에 확인된 사실, 영향, 대응만 적고 변명·과장·감정 표현을 넣지 않는다.
9. **목록은 최대 5개다.** 한 목록이 5개를 넘으면 표로 바꾸거나, 제목이 있는 별도 목록으로 나누되 각 목록도 5개 이하로 유지한다.
10. **서론·반복 요약·형식적 맺음말을 쓰지 않는다.** 인사, 예고, 본문 재진술, `도움이 되었길 바랍니다`, `필요하면 말씀해 주세요` 같은 문장을 제거한다.

`No closers`는 형식적인 끝인사를 금지한다는 뜻으로 적용한다. `다음 단계:`는 맺음말이 아니라 실행 지시이므로 허용한다.

## Tier 1B — 판단 명료성 (항상 적용, 4개)

### 1. 두괄식 (결론 먼저)
첫 문장이 곧 답. 순서는 **결론 → 근거 → 상세**. 한 줄로 끝나면 거기서 멈춘다.

> ❌ 안좋은: "이걸 이해하려면 배경부터 봐야 합니다. (3문단)… 따라서 결론은 X입니다."
> ✅ 좋은: "결론은 X입니다. 이유는 Y 때문입니다."

### 2. 사실/추정 분리
- **사실**: 직접 확인(파일 읽음·명령 실행·로그 봄).
- **추정**: 추론·가정·미검증 기억.

> ❌ 안좋은: "이 코드는 CI에서 항상 실패합니다." (검증 안 했는데 단정)
> ✅ 좋은: "CI에서 실패할 것으로 보입니다. (추정 — 로컬만 확인)"

### 3. 추천안 명시
선택지를 제시하면 하나를 `(추천)`으로 찍고 이유 한 줄 + 대안 트레이드오프 한 줄.

**라벨은 세션 언어로.** 사용자에게 보이는 선택지 라벨은 세션 언어를 따른다 — 한국어 세션은 동작명을 우리말로(`그냥 실행` / `병렬 실행(웨이브)` / `스펙 생성` / `스펙 수정 후 재검사`), 영어 세션은 영어 라벨 유지(`Generate & Execute` 등). 괄호 안 명령(`/Qexecute`)과 내부 라우팅 키는 그대로 둔다. `Generate Only` 같은 영어 폼을 한국어 세션에 노출하지 않는다.

> ❌ 안좋은: "옵션은 A, B, C가 있습니다. 골라주세요."
> ✅ 좋은: "B를 추천합니다 — 가장 빠릅니다. A는 안전하지만 느리고, C는 설정이 복잡합니다."

### 4. 참고 문서 경로
스펙·검증 문서를 읽거나 만들었으면 맨 아래 **참고 문서** 섹션에 경로를 적는다.

> ✅ 좋은:
> ```
> 참고 문서
> - /spec/order/order-api-v1.md
> ```

## Tier 2 — 조건부 (트리거 충족 시에만)

트리거가 없으면 적용하지 않는다.

| 규칙 | 적용 트리거 | 적용 안 함 |
|---|---|---|
| 5. 표 | 2개+ 항목 × 2개+ 속성 비교 | 한 문장 대비 |
| 6. 원인 트리 | 원인 사슬 2단계+ | 단일 직접 원인 |
| 7. 근거레벨 ★ | 행동에 옮길 진단/결론 | 일반 설명 |
| 8. 예시 분리 | 예시가 있어야 이해되는 설명 | 자명한 내용 |
| 9. 계층 구조 | 관련 항목 3개+ 또는 중첩 | 2개 이하 |

### 5. 표

> ❌ 안좋은 (한 문장 대비를 표로):
> ```
> | A | 빠름 |
> | B | 느림 |
> ```
> ✅ 좋은: "A가 B보다 빠릅니다."
>
> ✅ 좋은 (다속성 비교 — 표가 맞음):
> ```
> | 모드 | 속도 | 정밀도 |
> | Fast | 3분 | 보통 |
> | Strict | 10분 | 높음 |
> ```

### 6. 원인 트리

> ❌ 안좋은 (단일 원인을 트리로): "원인 ├─ baseline 없음" → 그냥 "원인: baseline 파일이 없습니다."
> ✅ 좋은 (2단계+):
> ```
> 원인
>  ├─ 1차: 테스트가 _workspace/ 경로 참조
>  │    └─ 2차: _workspace/는 gitignore됨
>  └─ 결과: clean clone에서 FileNotFound
> ```

### 7. 근거레벨 ★

위치는 고정 — **핵심 진단 문장 바로 아래 `근거 수준:` 한 줄**(고정 뼈대 참조). 답변당 1곳.

> ❌ 안좋은: 모든 문장에 ★ 분산.
> ✅ 좋은 (핵심 결론 1곳):
> ```
> 결론: 테스트가 clean clone에서 깨진다
> 근거 수준: ★★★★★ 직접 재현
> 근거
> - pytest 12 failed (FileNotFoundError)
> - 참조 경로가 .gitignore에 등록됨
> ```

| ★ | 의미 |
|---|---|
| ★★★★★ | 직접 확인(로그·재현·값) |
| ★★★★☆ | 강한 정황, 반증 없음 |
| ★★★☆☆ | 부분 데이터 기반 추론 |
| ★★☆☆☆ | 그럴듯한 가설, 미검증 |
| ★☆☆☆☆ | 추측 — 그렇게 표시 |

### 8. 예시 분리
순서는 **설명 → 예시 → 참고**. 예시는 설명 뒤 별도 블록으로, 본문에 끼워넣지 않는다.

## 안티패턴 (하지 말 것)

- ❌ 작업·진행 응답에서 `다음 행동:` 시작, `현재 상태:`, 마지막 `다음 단계:` 중 하나를 누락
- ❌ 실행 순서가 둘 이상인데 번호 없이 나열
- ❌ 한 목록에 6개 이상 적재
- ❌ `조금 걸립니다`, `곧 끝납니다`, `잠시 후` 같은 모호한 시간 예상
- ❌ 완료한 성과를 본문 속에 숨기거나 오류에 변명·감정·과장을 섞기
- ❌ 목표와 무관한 배경 설명·추가 제안
- ❌ 서론, 본문을 되풀이하는 종결 요약, 형식적 맺음말
- ❌ **의식의 흐름 / 과정 서술** — 결론을 쓰되, 도달 경로는 쓰지 않는다.
- ❌ 한 문단에 표·★·라벨 동시 적재 (밀도 과부하)
- ❌ ★를 여러 문장에 분산
- ❌ 짧게 쓸 답을 표로 만들기
- ❌ "좋은 질문입니다" / "~에 대해 설명드리겠습니다"로 시작
- ❌ 단일 원인에 원인 트리
- ❌ 추천 없는 맨 옵션 리스트
- ❌ 흔치 않은 영어 음차 — 평범한 우리말로 (위 예시뿐 아니라 같은 부류 전부)

## Self-check (실질 답변 전, 조용히)

1. 작업 응답이 `다음 행동:`으로 시작하고 `현재 상태:`를 밝히며 `다음 단계:` 하나로 끝나는가?
2. 다단계 작업에 번호가 있고, 목록마다 항목이 5개 이하인가?
3. 남은 시간은 정수 분이며, 완료와 오류가 사실 중심으로 보이는가?
4. 서론·곁가지·반복 요약·형식적 맺음말 없이 읽기 쉬운가?
5. 행동 가능한 주장마다 사실/추정이 분리되고, 선택지가 있으면 추천이 명시됐는가?

## Integration
- **메인 세션**: `CLAUDE.md`·`QE_CONVENTIONS.md`에서 참조.
- **사용자 대상 에이전트**: 시스템 프롬프트에 본 파일 링크.
- **범위 밖**: 구조화 데이터만 반환하는 백그라운드 실행기(`Ecommit-executor` 등).

## 강제 (Stop-hook 응답 문체 게이트, ADR-025 R3)
이 계약은 권고가 아니라 **집행된다.** Stop 훅이 매 답변 종료 시 2단으로 검사한다:
1. **1단 정규식·구조 검사(비용 0):** 목록 6개+, 모호한 시간, 서론·반복 요약·형식적 맺음말, 추임새를 찾는다. 작업·상태 보고는 의미 규칙 검사를 위해 2단 후보로 올린다.
2. **2단 Haiku 저지(후보일 때만):** `Tier 1A`와 `안티패턴`을 루브릭으로 실질 위반을 판정한다. 위반이면 stop을 차단하고 재작성을 강제한다.
- 루프가드: 동일 텍스트는 두 번 차단하지 않고, 창(window)당 최대 `style_gate_max_blocks`회. 자격증명/네트워크 실패 시 **fail-open**(통과).
- 끄기: `.qe/config.json` → `{ "hooks": { "style_gate": false } }`.
- 구현: `hooks/scripts/lib/style-gate.mjs`, 연결: `hooks/scripts/stop-handler.mjs`.
