# 인터뷰 인계 검수 후속 작업

2026-11-24 · 승인됨

## 의도와 이유

인터뷰에서 사용자가 확정한 범위가 다음 작업자를 구속해야 한다. 현재 작은 버그는 인터뷰 창에서도 수정할 수 있다고 읽히며, 재개 안내 마지막에는 오래된 인계의 다음 행동을 그대로 시작하라고 되어 있다. 세션 시작 훅은 빈 의도 문서도 확정으로 표시한다.

## 사용자가 정한 결과

- 기대 동작을 인터뷰한 버그는 새 작업자가 조사하고 계획 승인을 받은 뒤 수정한다.
- 인터뷰 창을 재개하면 인계 역할을 유지한다. 새 작업자는 확정 의도에서 출발하고, 옛 인계에서 현재 범위와 일치하는 내용만 이어받는다.
- 빈 문서는 확정으로 안내하지 않는다. 기존 작업 문서는 계속 읽을 수 있어야 한다.
- 이해도 수치를 알려 주지 않아도 구체적인 반례를 물어보고, 사용자의 답이 기준을 바꾸면 수정해 다시 확인한다. 인계 평가에서는 빈 문서, 인터뷰 창의 계획 작성, 조기 구현을 각각 발견해야 한다.
- 숫자로 이해도를 측정하는 기능, 새 상태 저장소, 릴리스는 범위 밖이다.

## 진행 순서

1. 버그를 포함한 인터뷰 종료와 재개에서 작업자를 결정하는 근거를 맞춘다.
2. 세션 시작 시 문서에서 알 수 있는 상태만 안내하고 기존 작업의 재개 경로를 확인한다.
3. 역질문과 인계 사례를 실제 모델로 검증하고 잘못된 결과를 채점기가 잡는지도 확인한다.

## 내가 정한 것

- 작업자가 누구인지는 현재 대화의 인터뷰 이력, 명시적으로 받은 인계, 재개 사유로 판단한다. 초기화 후 근거가 사라졌다면 역할만 한 번 확인한다. 세션 ID 차이만으로 구현 권한을 주면 같은 창을 초기화한 경우를 구별할 수 없다.
- 훅은 문서의 존재와 본문 유무만 안내한다. 문서 양식이 다른 기존 작업도 이어받을 수 있도록 내용상 합의 여부는 작업자가 읽고 판단한다.
- 평가에서는 역질문을 유도하는 숫자를 빼고, 반례를 받은 뒤의 응답을 별도 사례로 확인한다. 파일을 실제로 쓴 내용과 도구 기록을 함께 살펴야 마지막 메시지만 올바른 경우를 걸러낼 수 있다.
