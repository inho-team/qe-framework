# 인터뷰 인계 검수 후속 작업

## 왜 하는가

인터뷰에서 합의한 내용이 실제 실행 주체와 범위를 결정해야 한다. 메인 세션과 레드팀 검수에서 같은 창의 버그 수정, 재개 시 역할 혼동, 빈 문서의 확정 표시, 평가의 거짓 합격 경로가 발견됐다.

## 원하는 결과와 완료 기준

- 기대 동작을 인터뷰로 확인한 버그도 새 작업자가 이어받고 인터뷰 창은 직접 수정하지 않는다.
- 새 작업자와 기존 인터뷰 세션이 각자의 역할로 재개하며, 확정 의도와 어긋나는 오래된 인계를 따르지 않는다.
- 빈 의도 문서를 확정된 작업으로 표시하지 않는다. 기존 작업 문서도 이어받을 수 있어야 한다.
- 사용자가 숫자를 알려 주지 않은 사례에서 역질문하고, 반례 답변을 받으면 완료 기준을 수정한다. 인계 평가가 빈 문서, 같은 창에서 작성한 계획, 조기 구현을 잡는지 확인한다.

## 이번에 하지 않을 일

95%를 통계적으로 측정하거나 새 DB·상태 파일을 도입하지 않는다. 릴리스는 이번 작업 범위 밖이다.
