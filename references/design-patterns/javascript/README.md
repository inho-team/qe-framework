# JavaScript 디자인 패턴

`package.json`과 기존 import를 확인해 ESM과 CommonJS 중 프로젝트가 쓰는 모듈 방식을 따른다. 실제로 지원하는 브라우저와 Node.js 버전도 확인한다. 언어 문법이 같아도 `node:events`처럼 런타임이 제공하는 API는 다르다. JavaScript에서는 함수, 모듈, 객체 합성만으로도 호출 계약과 상태의 수명을 표현할 수 있다.

| 구현 방식 | 선택 기준 |
| --- | --- |
| [Module](module.md) | 내부 구현을 숨기고 여러 호출자가 사용하는 공개 API를 정한다. |
| [Factory](factory.md) | 호출할 때마다 독립 상태를 만들거나 설정에 맞는 구현을 조립한다. |
| [Strategy](strategy.md) | 호출 방식은 유지하면서 할인이나 분류 같은 정책을 교체한다. |
| [Decorator](decorator.md) | 기존 함수의 호출 계약을 유지하면서 계측이나 캐시를 덧붙인다. |
| [Middleware](middleware.md) | 요청이 거치는 단계의 순서와 조기 종료 방식을 제어한다. |
| [Observer](observer.md) | 생산자가 소비자를 직접 호출할 필요 없이 여러 곳에 변경을 알린다. |
| [Adapter](adapter.md) | 외부 데이터나 호출 규약을 내부 계약으로 변환한다. |
| [Facade](facade.md) | 여러 하위 API를 조율해 호출자에게 도메인 작업 하나를 노출한다. |
| [State](state.md) | 현재 상태에 따라 허용되는 요청·완료·취소·재시도를 다르게 처리한다. |

같은 상황에 패턴을 함께 적용할 수 있다. 예를 들어 모듈이 팩토리를 내보내면 공개 API는 한곳에 유지하고 요청 상태는 호출마다 새로 만들 수 있다. 요청 파이프라인의 중간 단계에서 개별 서비스를 감쌀 때는 데코레이터와 미들웨어를 함께 쓸 수 있다.

## 예시 실행

예시는 별도 표기가 없으면 Node.js 20 이상을 대상으로 하며 외부 패키지를 쓰지 않는다. 단일 파일 예시는 사례별로 별도 디렉터리를 만들어 `example.mjs`에 저장하고, 그 디렉터리에서 `node --test example.mjs`를 실행한다. 여러 파일이 필요한 경우에는 사례에 적힌 파일명과 실행 명령을 따른다. 브라우저에서 쓰는 API가 등장하는 예시도 Node.js용 검증 코드는 `node:` import를 사용한다.
